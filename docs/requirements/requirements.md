# Requirements

## Контекст

Документ містить актуалізований каталог вимог до навчального проєкту

Task Manager, сформований на основі результатів ПЗ2.

Вимоги використовуються як основа для побудови UML-моделей 
та архітектурного проєктування у ЛР2.

## Функціональні вимоги

| ID    | Формулювання                                     | Пріоритет | Критерій приймання                                          | Джерело             |
|-------|--------------------------------------------------|-----------|-------------------------------------------------------------|---------------------|
| FR-01 | Користувач може створити нову задачу             | Must      | Після введення валідних даних задача з'являється у списку   | UC-01 Create Task   |
| FR-02 | Користувач може переглядати список власних задач | Must      | Система повертає список задач поточного користувача         | UC-02 View Tasks    |
| FR-03 | Користувач може змінити статус задачі            | Must      | Допустимий перехід змінює статус, недопустимий відхиляється | UC-03 Change Status |

## Нефункціональні вимоги

| ID     |Quality Attribute| Формулювання                                                       |Пріоритет |   Як перевіряється                                 |
|--------|-----------------|--------------------------------------------------------------------|----------|----------------------------------------------------|
| NFR-01 | Maintainability | Бізнес-логіка не повинна залежати від UI та конкретної БД          | Must     | Domain/Application можна тестувати без UI і SQLite |
| NFR-02 | Security        | Секрети не повинні зберігатися у Git-репозиторії                   | Must     | `.env`, tokens і passwords відсутні у repository   |

| NFR-04 | Usability       | Помилки введення повинні супроводжуватися зрозумілим повідомленням | Should   | Перевірка сценаріїв невалідного введення           |

## Architecture-Significant Requirements

### ASR-01
Related requirement: NFR-01

Business logic must be independent of UI and persistence.

Architectural impact:
потрібно розділити Presentation, Application/Domain
та Infrastructure.

### ASR-02
Related requirement: NFR-02

Secrets must not be stored in the repository.

Architectural impact:
configuration and secrets must be externalized.

### ASR-03
Related requirement: NFR-03

95 % read operations must complete within 500 ms.

Architectural impact:
необхідно врахувати спосіб доступу до даних,
обсяг вибірки та можливість оптимізації query path.

## Constraints
- мова реалізації: C#;
- платформа: .NET 10;
- система керування версіями: Git;
- repository: GitHub;
- локальне зберігання: SQLite;
- архітектурна документація зберігається у docs/.
